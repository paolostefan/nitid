# Structs

There's no real OOP in Nitid, but structs are as close as OOP objects as possible.

Structs in Nitid work pretty much as Go structs.

## Reserved keywords

Here are the field and method names you must avoid:

* `self` refers to the struct which is calling a specific method (like in Python). No members can have this name.
* `bytesize()` is a reserved method which calls C's `sizeof()` to return the struct size in bytes.

## Data members

A struct must contain at least one data member, any type is allowed.

Data members must be declared by specifying their **name**, followed by a colon (`:`), their **type** and a semicolon
(`;`).

Members name must follow identifier syntax, so no initial numeric digits, no punctuation, etc.

```c++
struct Person {
  name: string;
  age: u8;
};
```

### Array members

A struct can have any number of array members, declared in either of the following ways.

```c++
// C-style array member declaration
struct CacheLine {
  data: u8[64];
};

// Alternate array member declaration
struct CacheLine {
  data: [64 u8];
};
```

Initialization of array struct members follows the usual way.

```c++
c := CacheLine{ data: {1,2,3,4,5} }; // members from the 6th on will be zero-initialized
```

## Methods

Structs in Nitid can have their own methods.

---

ℹ️ **Important**: the `self` keyword denotes the struct which is calling the method, just as in Python. In Nitid, `self`
needs not be declared in the method signature.

---

```c++
struct Circle {
  color: string;
  radius: f32;
};

impl Circle {
  fn greet() -> string {
    return "Hello, I'm " + self.color;
  }
    
  fn area() -> f32 {
    return self.radius * self.radius * 3.14159;
  }
};
```

## Instancing

Struct instances are declared just like scalar or array variables. Data members can be inlined in the declaration.

```c++
c := Circle{ color: "red", radius: 1.5 };
```

## Accessing members

Members and methods are referenced using a dot (`.`) after the variable name.

```c++
r := c.radius; // r type is f32
c.greet();     // returns "Hello, I'm red"
c.area();      // returns 7.0685775
```

## Composition / Embedding

A struct can embed another struct anonymously, promoting the inner struct's fields and methods to the outer one
(Go-style composition over inheritance).

```c++
struct Employee {
  name: string;
  id: u32;
};

impl Employee {
  fn describe() -> string {
    return "Employee " + self.id + ": " + self.name;
  }
};

struct Manager {
  Employee;        // embedded — no field name
  department: string;
  directReports: u32;
};

impl Manager {
  fn teamSize() -> u32 {
    return self.directReports;
  }
};
```

Fields and methods of the embedded type are accessed directly on the outer type:

```c++
m := Manager{
  Employee: Employee{name: "Alice", id: 1001},
  department: "Engineering",
  directReports: 5,
};

m.name;       // "Alice" — promoted from Employee
m.id;         // 1001   — promoted from Employee
m.describe(); // "Employee 1001: Alice" — promoted method
m.teamSize(); // 5
```

If the outer struct defines a field or method with the same name, it shadows the embedded one. The embedded field can
still be accessed explicitly via its type name:

```c++
m.Employee.name; // explicit access, bypasses shadowing
```

Multiple embedding is allowed. Name conflicts between embedded types produce a compile error.

## Method Receiver

In Nitid, `self` is always a pointer to the receiving struct. No value receiver exists — this avoids implicit copies and
makes mutation explicit by default.

```rust
struct Counter {
  value: i64;
};

impl Counter {
  fn inc() {
    self.value = self.value + 1; // mutates through pointer
  }

  fn get() -> i64 {
    return self.value;
  }
};
```

Pointer receiver means the method can modify the struct, and calling a method never copies the struct.

```c++
c := Counter{value: 10};
c.inc();
c.inc();
c.get(); // 12
```

Methods are statically resolved and desugared to plain function calls (`Counter_inc(&c)`). No dynamic dispatch.

## Memory Layout

By default, struct layout follows C ABI rules: fields are aligned to their natural alignment and padding is inserted
between fields.

The `packed` keyword forces the struct to omit padding:

```c++
packed struct NetPacket {
  flags: u8;
  length: u16;     // adjacent to flags, no padding
  checksum: u32;   // adjacent to length, no padding
};
```

Useful for wire protocols, file formats, and hardware registers.

The `align(N)` attribute sets minimum alignment of the struct as a whole:

```c++
align(64) struct CacheLine {
  data: u8[64];
};
```

Layout attributes compose:

```c++
packed align(4) struct Header {
  version: u8;
  kind: u8;
  size: u32;
};
```

## Tags

---

**📝 PLEASE NOTE**: struct tags are an **unimplemented** feature, still in draft status. **Do not rely on it yet**.

---

Struct fields can carry arbitrary metadata as string tags, modeled after Go struct tags. Tags are optional string
literals following the field type.

```c++
struct User {
  name:  string "json:'name' xml:'name'";
  email: string "json:'email,omitempty'";
  age:   u8     "json:'age' validate:'min=0,max=150'";
};
```

Tags are not interpreted by the language. They are stored as metadata for serialization, validation, ORM mapping, form
parsing, and code generation tools.
