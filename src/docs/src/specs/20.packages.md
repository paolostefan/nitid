# Packages

Nitid code can be organized in **packages**, which closely resemble Go packages.

A package is a collection of source files containing functions, structures, enumerations, etc. sharing the same logical
scope.



### Defining packages

To indicate that a source file belongs to a specific package, the first non-comment line of that file must contain the
`package` keyword followed by the package name and a semicolon.

```nitid
// The file can start with as many comments+whitespace as you like,
// but no valid code must appear before the "package" keyword.
  
package Bubble; // This file belongs to the "Bubble" package.
  
// ... your code  
```  

### Using packages

In order to make a specific package visible to the Nitid code, the package must be imported using the `import`
keyword followed by the package name, just like this: `import PackageName;`

Then, everything in the package can be accessed by prepending the package name and a dot (`.`).

```nitid
import Bubble; // Make the Bubble package visible here  

// Call the "someFunction" function of the Bubble package  
a := Bubble.someFunction();

// Access the "someVar" variable of the Bubble package
b := Bubble.someVar;

// Access the "SOME_VALUE" variant of the someEnum enum of the Bubble package
c := Bubble.someEnum.SOME_VALUE;
```  

An imported package name can be aliased using the `as` keyword.

```nitid
import Bubble as b; // Make the Bubble package visible and alias it to "b"  

// Call the toplevel "someFunction" function of the Bubble package
a := b.someFunction();   

// Error: Bubble is not available since it is aliased to "b"
e := Bubble.someFunction();
```  

The alias renames only the name you write at the call site. **Mangled C symbols always use the package's own
declared name**, so the caller and the imported translation unit agree on the prefix:

```nitid
// gfx/window.nt
package gfx;
fn window_open(u8 *title, int w, int h) -> void * { /* ... */ }
```

```nitid
// main.nt
import gfx as g;
void *win = g.window_open("hello", 640, 480);   // calls gfx_window_open(...)
```

Two consequences follow:

- **`extern "C"` declarations inside a package are never mangled and never exported.** They name real C symbols, so
  `extern "C" fn SDL_Init(u32) -> int;` stays `SDL_Init` and is not reachable as `pkg.SDL_Init(...)`. All such
  prototypes are emitted together at the top of the file, before anything that calls them, so their position in the
  source is irrelevant (C99 would reject a call that precedes its prototype).
- **Qualified calls work anywhere an expression is expected**, including inside a variable initializer
  (`void *win = g.window_open(...)`), not only as a bare statement.

⚠️ **Imported struct types cannot be named.** `gfx.Window w = ...;` and `w := gfx.Window{ ... };` are parse errors
(`Expected Semicolon, found Ident("w")` / `Expected Semicolon, found LBrace`), and there is no plain `type` alias to
work around it — only `fn`-pointer aliases exist. The cross-package surface therefore has to stay at `void *` handles
and free functions; a struct wrapper is usable only inside its own package. See
[Modules](21.module-layout.md).
