# Packages

Nitid code can be organized in **packages**, which closely resemble Go packages.

A package is a collection of source files containing functions, structures, enumerations, etc. sharing the same logical
scope.



### Defining packages

To indicate that a source file belongs to a specific package, the first non-comment line of that file must contain the
`package` keyword followed by the package name and a semicolon.

```go
// The file can start with as many comments+whitespace as you like,
// but no valid code must appear before the "package" keyword.
  
package Bubble; // This file belongs to the "Bubble" package.
  
// ... your code  
```  

### Using packages

In order to make a specific package visible to the Nitid code, the package must be imported using the `import`
keyword followed by the package name, just like this: `import PackageName;`

Then, everything in the package can be accessed by prepending the package name and a dot (`.`).

```go
import Bubble; // Make the Bubble package visible here  

// Call the "someFunction" function of the Bubble package  
a := Bubble.someFunction();

// Access the "someVar" variable of the Bubble package
b := Bubble.someVar;

// Access the "SOME_VALUE" variant of the someEnum enum of the Bubble package
c := Bubble.someEnum.SOME_VALUE;
```  

An imported package name can be aliased using the `as` keyword.

```go
import Bubble as b; // Make the Bubble package visible and alias it to "b"  

// Call the toplevel "someFunction" function of the Bubble package
a := b.someFunction();   

// Error: Bubble is not available since it is aliased to "b"
e := Bubble.someFunction();
```
