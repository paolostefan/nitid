# Enumerations

`enum`s in Nitid work about the same way as in C++.

The name of both the `enum` and its members must follow the identifier names rules.

Member values **may be declared explicitly**; if not declared, values start from `0` and are incremented by `1` at each
step.

`enum`s can be **untyped**, in which case the `i32` type will be silently used.

```c++
// Implicit i32 type
enum AccessMode {
    NONE = 0, // not needed: 0 is the default start value
    READONLY,
    WRITEONLY,
    READWRITE
};
```

Or, the `enum` can be typed explicitly.

```c++
// Explicit types
enum ByteAccessMode : u8 {
    NONE,
    READONLY,
    WRITEONLY,
    READWRITE
};

// With signed types, negative values are legal
enum FileType : i16 {
    Error = -1,
    Unknown,
    Jpeg,
    Png,
    Text = 0x1000,
};
```

In both cases, the `enum` values are checked at compile time to make sure they fit in the `enum` type with no overflows.

```c++
// 8-bit unsigned int overflow at the second value 
enum Wrong : u8 {
    NONE = 255,
    A_VALUE,
    ANOTHER_VALUE,
};
```

## Caveats

Only integral types are allowed. Trying to use float types, strings or struct types will result in a compile error.

```c++
// Error: no float type allowed in enums
enum Wrong : f64 {
    One = 1.0,
    Two,
    Three,
};

// Error: no string/compound type allowed in enums
enum Wrong : string {
    One = "One",
    Two,
    Three,
};
```
